# המרפאה הקרדיולוגית הווירטואלית

כלי סימולציה לימודי לתלמידי מדעי הבריאות בתיכון. התלמיד מנהל קבלה בקופת חולים בשפה חופשית, מבצע בדיקה ובדיקות, מנמק החלטות לפרופ׳ שחף, כותב רשומה רפואית ומסביר למטופל. המערכת מפיקה משוב איכותני ודוח PDF.

זהו **אתר סטטי** (React + Vite, בלי שרת). הדפדפן פונה ישירות לספק ה-AI. הספקים והמודלים מוגדרים ב-`data/providers.json`. כרגע רק OpenAI הוא מסלול שהיה בשימוש; ספקים אחרים (xAI, Groq, Gemini, OpenRouter, Mistral) מוגדרים אך **לא נבדקו מול השירות האמיתי**. מורה יוצר **קישור כיתה** שמכיל את המפתח; תלמידים פותחים את הקישור ולא רואים שדה מפתח.

## הרצה ובדיקה מקומית

דרישות: Node.js `>=22.13.0`.

```bash
npm ci --ignore-scripts   # התקנה לפי קובץ הנעילה
npm run dev               # שרת פיתוח, בדרך כלל http://localhost:5173
npm run build             # בנייה ל-dist/
npm run preview           # הצגת הבנייה המקומית
npm test                  # בנייה ואז כל הבדיקות (לא פונות לשירות AI; הספק מוחלף בזיוף)
npm run typecheck
npm run lint
```

הבדיקות לא משתמשות במפתח אמיתי ולא שולחות בקשות רשת. הרצת הסימולציה עם AI אמיתי דורשת מפתח API.

## מבנה

- `src/` — הממשק: `App.tsx` (הסימולטור), `TeacherSetup.tsx` (הקמת כיתה) ונקודת הכניסה `main.tsx`.
- `lib/` — הלוגיקה: `simulation.ts` (שלבי השיחה והבדיקות), `feedback.ts` (המשוב), `ai-client.ts` (שכבת ספקים אחידה: מתאם Responses ומתאם Chat Completions), `providers.ts` (קריאת הגדרות הספקים), `case-catalog.ts` (רשימת מקרים בטוחה לדפדפן), `case-data.ts` (קריאת נתוני מקרה), `case-loader.ts` (טעינה עצלה), `session-store.ts` (שמירת התקדמות בדפדפן), `class-link.ts` (קישור כיתה והגבלות רכות).
- `data/cases/` — קבצי המקרים (JSON) וקטלוג `index.json`.
- `data/source/` — קבצי ה-Excel המאושרים. `scripts/import-case-data.py` ממיר אותם ל-JSON (דורש Python ו-openpyxl; לא נבדק על מחשב זה).
- `tests/` — בדיקות. `types/` — הגדרות טיפוסים.

## מקרים

המקרים נטענים מהקטלוג `data/cases/index.json`, כל אחד כקובץ נפרד שנטען רק כשהתלמיד בוחר אותו. הוספת מקרה: קובץ JSON תקין בתיקיית `data/cases/` ושורה בקטלוג. `tests/case-catalog.test.mjs` בודק מזהים כפולים, שדות חסרים, אי-התאמה לקובץ, וקובץ שלא נכלל בקטלוג. התלונה המרכזית והמגבלה `maxAnamnesisFacts` נכתבות כרגע ידנית בקטלוג (אינן בקבצי ה-Excel).

עובדות קליניות, תוצאות, פרסונה ורובריקות מקורן בקבצי הנתונים המאושרים, לא בקוד. אין לשנות עובדה קלינית בלי אישור.

## קישור כיתה (למורים)

פותחים את הכתובת של האתר עם `#/setup`, מזינים מפתח API, בוחרים ספק ומודל, מגדירים הגבלות ותוקף, ומקבלים קישור לשליחה לתלמידים (`#c=…`). ההגדרות נשמרות בחלק ה-`#` של הכתובת, שאינו נשלח לשרת.

- **המפתח גלוי בקישור ובדפדפן של התלמיד** ואינו מוצפן; תלמיד שמבין יכול לחלץ אותו. לכן המורה מקבל אזהרה לפני יצירת הקישור, ומומלץ מפתח ייעודי חינמי או עם תקרת הוצאה. העלות והאחריות על המורה.
- **ההגבלות רכות** (מספר פניות לתלמיד, אורך תשובה, תוקף): הן נאכפות בדפדפן ואפשר לעקוף אותן. ההגנה האמיתית היא המכסה אצל הספק.
- התלמיד רואה הודעה על כך ששיחתו נשלחת לספק, לפי `dataNotice` של הספק ב-`data/providers.json`.
- כתובת הספק לא נקראת מהקישור, אלא רק מ-`data/providers.json`.

## מצב ומה הלאה

- **נתוני המקרה גלויים לתלמיד** (הם קבצים באתר הסטטי). זו החלטה מכוונת.
- **שמירת ההתקדמות** היא בדפדפן בלבד; קוד השחזור פועל רק באותו דפדפן ומכשיר.
- **ספקים:** רק OpenAI היה בשימוש; האחרים לא נבדקו מול שירות אמיתי. "בדוק חיבור" בעמוד ההקמה שולח בקשה קצרה במפתח המורה, ביוזמתו.
- הפרסום (GitHub Pages) טרם הוגדר.
