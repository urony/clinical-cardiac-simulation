# כלי יצירת מקרים בשורת פקודה (מקומי, רק אצלך)

> יש גם ממשק גרפי מקומי לאותה מטרה: [case-admin.md](case-admin.md) (`npm run admin`).

הכלי רץ על המחשב שלך בלבד. הוא לא נפרס לאתר, ומורים אינם יכולים להשתמש בו. הוא עוזר להפוך תיאור חופשי של מקרה לתיק מלא בתבנית ה-Excel, לבדוק אותו, ולהוסיף אותו לאתר **רק אחרי שאישרת**.

## תהליך העבודה

```bash
npm run case -- brief מקרה-חדש          # יוצר drafts/מקרה-חדש/brief.md לתיאור המקרה
# ממלאים את brief.md בעברית חופשית
npm run case -- draft drafts/מקרה-חדש/brief.md                 # מציג תוכנית ועלות, לא שולח כלום
npm run case -- draft drafts/מקרה-חדש/brief.md --yes           # ה-AI ממלא את התבנית (שולח בקשות לספק במפתח שלך)
# פותחים את drafts/CASE-004/CASE-004-draft.xlsx ב-Excel, עוברים על הכול ומתקנים
npm run case -- approve drafts/CASE-004/CASE-004-draft.xlsx    # אחרי הסקירה: "טיוטה" -> "מאושר"
npm run case -- validate drafts/CASE-004/CASE-004-draft.approved.xlsx --chief-complaint "..."
npm run case -- publish  drafts/CASE-004/CASE-004-draft.approved.xlsx --chief-complaint "..."          # תוכנית בלבד
npm run case -- publish  drafts/CASE-004/CASE-004-draft.approved.xlsx --chief-complaint "..." --yes    # מוסיף לאתר
```

אחרי `publish --yes` מריצים `npm test`, ומבצעים commit בעצמך (הכלי לא עושה commit ולא push).

## מה ה-AI עושה ומה לא

- ממלא רק את מה שהתבנית דורשת: תשובות אנמנזה, ממצאי בדיקה גופנית, תוצאות מספריות, פרשנות בדיקות, בדיקות המשך, החלטות וטיפול וכללי משוב, ופרטי המטא של המקרה.
- **טיוטה בלבד.** כל פריט שה-AI המציא או אינו בטוח בו מסומן בצהוב בקובץ ה-Excel, והגיליון `טיוטת_AI` מונה אותם עם הערה. תאים כחולים מולאו על ידי ה-AI ולא סומנו לבדיקה, אבל גם אותם צריך לבדוק.
- ההוראות שלו: להתבסס על התיאור, לא להמציא אבחנות, תרופות או ממצאים חריגים, לשמור על עקביות עם מה שכבר נקבע, ולא לחשוף את האבחנה בפתיחה.
- אין שום פרסום אוטומטי: הסטטוס נשאר "טיוטה" עד שתריץ `approve`, ו-`publish` דורש `--yes` מפורש.

## מה הבדיקה (`validate`) תופסת

מזהים חסרים או כפולים לעומת התבנית, סטטוס שנשאר "טיוטה", חשיבות שאינה אחת מארבעת הערכים המוכרים, שדות ריקים, הוראות תבנית שלא הוחלפו, ערך מספרי חסר, מין או גיל לא תקינים, ונוסח פתיחה או תלונה מרכזית שחושפים את האבחנה. שלושת המקרים המאושרים עוברים אותה ללא שגיאות. **הבדיקה מבנית; היא לא בודקת נכונות רפואית.** זו אחריותך.

## דרישות

- Node (כבר קיים בפרויקט) ו-Python 3 עם `openpyxl` להמרת Excel. אם Python אינו נמצא אוטומטית, הגדירו `CASE_TOOL_PYTHON` לנתיב של `python.exe`.
- למילוי בעזרת AI: משתנה הסביבה `CASE_TOOL_API_KEY` (המפתח שלך), ואופציונלית `CASE_TOOL_PROVIDER` (ברירת מחדל `openai`, מתוך `data/providers.json`) ו-`CASE_TOOL_MODEL`. הגדירו אותם בחלון הפקודות בלבד, לא בקובץ. המפתח לא נכתב לדיסק ולא מודפס.
- הפקודה `draft --yes` שולחת את תיאור המקרה ועובדות שנקבעו לספק ועולה כסף לפי תעריפו. בלי `--yes` מוצגת רק תוכנית (כמה קריאות).

## מגבלות ידועות

- כרגע ה-AI ממלא רק את שורות התבנית הקיימות (89 אנמנזה, 45 בדיקה גופנית, 33 בדיקות מיידיות, 9 בדיקות המשך, 5 החלטות, 30 כללי משוב). להוסיף שורות החלטה או בדיקות חריגות אפשר ידנית ב-Excel.
- התלונה המרכזית (מה שהתלמיד רואה לפני הפגישה) אינה חלק מה-Excel. מזינים אותה ב-`publish --chief-complaint`.
- הכלי נבדק בבדיקות עם מודל מזויף. **הוא עדיין לא הורץ מול ספק AI אמיתי.** ההרצה הראשונה צריכה להיות על מקרה פשוט, ובסקירה מלאה.
- ראו גם [case-brief-template.md](case-brief-template.md) לתבנית התיאור.
