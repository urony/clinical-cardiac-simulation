# ממשק ניהול מקרים (מקומי)

דף שרץ על המחשב שלך בלבד ומאפשר להוסיף מקרה חדש: לתאר אותו, להפיק טיוטה בעזרת AI, לעבור עליה ולערוך, ולהוסיף אותו לאתר. הוא **לא** חלק מהאתר הציבורי, ומורים לא יכולים להגיע אליו.

## הפעלה

**הכי פשוט (Windows):** לחיצה כפולה על הקובץ `start-admin.bat` בתיקיית הפרויקט. הוא מפעיל את הממשק ופותח אותו בדפדפן. סוגרים את החלון השחור כדי לעצור.

או בחלון הפקודות:

```bash
npm run admin            # עם AI אמיתי (צריך מפתח, ראו להלן)
npm run admin -- --demo  # הדגמה: טקסט דוגמה, בלי AI ובלי עלות, ואי אפשר להוסיף לאתר
```

ואז לפתוח בדפדפן את `http://127.0.0.1:4180/` (הכתובת מודפסת). לעצירה: Ctrl+C. מומלץ להתחיל בהדגמה כדי להכיר את המסכים.

## ארבעה שלבים

1. **תיאור המקרה.** טופס בעברית חופשית: נושא ואבחנה, מטרות למידה, המטופל, אנמנזה, בדיקה גופנית, בדיקות, החלטות וטיפול. בנוסף **תלונה מרכזית** (מה שהתלמיד רואה לפני הפגישה, ללא אבחנה). הכול נשמר אוטומטית.
2. **הפקת טיוטה.** בוחרים ספק ומוסיפים מפתח API (נשמר בזיכרון של השרת המקומי בלבד, לא בקובץ, ולא מוחזר לדף). מוצגת תוכנית: כמה קריאות למודל (כ-15). אפשר גם **טיוטה ריקה** ולמלא ידנית.
3. **סקירה ועריכה.** כל הגיליונות (פרטי המקרה, אנמנזה, בדיקה גופנית, תוצאות מספריות, בדיקות בסיסיות, בדיקות המשך, החלטות, כללי משוב). אפשר לסנן "רק פריטים לבדיקה" או "רק ריקים". פריט שה-AI סימן (צהוב) חייב לקבל וי "בדקתי את הפריט". עריכות נשמרות לבד.
4. **בדיקה והוספה לאתר.** מוצגת רשימת מה חוסם. ההוספה אפשרית רק כש: אין שגיאות בדיקה, כל הפריטים המסומנים אושרו, יש תלונה מרכזית, וסימנת "בדקתי את התוכן הקליני ואני אחראי עליו". אחרי הלחיצה נכתבים הקבצים בפרויקט (ללא commit ולא פרסום).

## פריטים נוספים: מקרים שאינם קרדיאליים

הרשימות הבסיסיות (89 שאלות, 45 רכיבי בדיקה גופנית, 33 בדיקות בסיסיות, 9 בדיקות המשך) זהות לכל מקרה. מקרה יכול להוסיף **פריטים משלו**, למשל במקרה כליה: שאלה על כאב מותן, בדיקת רגישות בבית הכליה, תרבית שתן עם ספירת מושבות, וביופסיית כליה.

- **בשלב 3** (סקירה ועריכה), בתחתית כל לשונית של אנמנזה, בדיקה גופנית, בדיקות בסיסיות ובדיקות המשך, יש **"+ הוסף פריט שאין ברשימה"**. נותנים לו שם וממלאים את השדות שלו כמו כל פריט אחר. פריט נוסף מסומן "פריט נוסף של המקרה" ואפשר למחוק אותו.
- **תוצאה מספרית** (עם יחידה וטווח ייחוס) נוספת בלשונית "תוצאות מספריות", ושייכת לבדיקה נוספת של המקרה (תוסיפו קודם את הבדיקה). לבדיקה נוספת בלי תוצאות מספריות חובה למלא "תוצאה להצגה".
- **בצ'אט:** בקבוצה האחרונה של מסמך העבודה (16 מתוך 16) ה-AI מציע פריטים נוספים שהמקרה דורש, ואתה מדביק אותם כמו כל קבוצה. אותו פריט שמודבק שוב מתעדכן ולא מוכפל.
- **בדיקות:** פריט נוסף חייב לקבל אותם שדות חובה כמו פריט רגיל (תשובה, חשיבות, היגיון), והבדיקה חוסמת פריט ריק. פריטים נוספים מקבלים קוד `X-…` (`X-AN-001`, `X-IT-001`, `X-IT-001-N1`), ייחודי למקרה.
- **באתר:** הסימולטור קורא אותם כמו כל פריט אחר: התלמיד יכול לשאול עליהם ולבקש אותם, והם נכנסים למשוב.

מה שעדיין לא נעשה: כותרת האתר נשארת "המרפאה הקרדיולוגית הווירטואלית", ודוגמאות ההסבר בשלבים (אק״ג, אקו) נשארו קרדיולוגיות. אין עדיין "חבילות התמחות" לשימוש חוזר, ואי אפשר להסתיר פריט בסיסי שלא רלוונטי למקרה (במקום זה כותבים לו תשובה תקינה בחשיבות נמוכה).

## עבודה עם ה-AI שלך בצ'אט (בלי עלות API)

אם יש לך כבר AI שאתה עובד איתו בצ'אט (ChatGPT, Claude, Gemini ועוד), אפשר להכין איתו את המקרה בלי לשלם על קריאות API, ולהשאיר את הצ'אט של הפיתוח נקי:

1. בשלב 2, לחץ **"הורד מסמך עבודה ל-AI"**. זה קובץ אחד (Markdown) עם הוראות ל-AI, הכללים, הפורמט, התיאור שכתבת בשלב 1, ורשימת **16 קבוצות** של פריטים להפקה (האחרונה: פריטים נוספים שהמקרה דורש).
2. העלה אותו לצ'אט שלך וכתוב: "קרא את המסמך ובצע את ההוראות בו". ספר לו על המקרה במילים שלך. הוא ישאל שאלות. כשהכול ברור כתוב "התחל", ואחר כך "המשך" אחרי כל קבוצה. בכל הודעה הוא נותן בלוק JSON אחד.
3. העתק את התשובות (קבוצה אחרי קבוצה, או את כל השיחה בבת אחת) לתיבה בשלב 2 ולחץ **"ייבא"**. הממשק מוצא את בלוקי ה-JSON בתוך השיחה (גם בין טקסטים, וגם עם פסיק מיותר), ומציג כמה נקלטו, ומה לא נקלט ולמה.
4. ממשיכים כרגיל: סקירה ועריכה בשלב 3, ואז בדיקה והוספה בשלב 4.

פריט שלא נקלט (מזהה לא מוכר, עמודה חסרה, חשיבות לא תקינה, שנשאר בו טקסט תבנית) מוצג בשמו עם הסיבה; אפשר לבקש מה-AI לתקן ולהדביק שוב. פריטים שכבר ערכת בעצמך לא נדרסים. אין שום קריאה לשירות חיצוני בשלב הזה.

## אחרי ההוספה: פרסום באתר

בסוף שלב 4 יש כפתור **"פרסם באתר החי"**. הוא מבצע לבד, בסדר הזה, ועוצר ברגע שמשהו נכשל:

1. בודק שהשינויים בפרויקט הם רק קובצי המקרה (אחרת הוא מסרב ומציג מה השתנה).
2. מריץ את הבדיקות (`npm test`, כדקה).
3. שומר ב-git (commit) **רק** את `data/cases` ו-`data/source`.
4. שולח ל-GitHub (push). האתר הציבורי מתעדכן בעצמו כדקה-שתיים אחרי זה.

כל שלב מוצג עם ✓ או ✗, ואם משהו נכשל מוצג הפלט. הכפתור דורש אישור, וזמין רק למקרה שכבר נוסף לקבצי הפרויקט. אם תעדיף לעשות זאת ידנית:

```bash
npm test
git add data && git commit -m "Add CASE-004" && git push
```

הדחיפה דורשת שהמחשב מחובר ל-GitHub (אותו חיבור שבו אתה משתמש ב-git כרגיל).

## בטיחות

- השרת מאזין רק ל-127.0.0.1, כל קריאה דורשת אסימון אקראי שנוצר בכל הפעלה, ובקשות מאתרים אחרים נדחות.
- המפתח לא נכתב לדיסק ולא מודפס. הוא נעלם כשסוגרים את השרת.
- שום דבר לא מגיע לנתוני האתר בלי אישור מפורש שלך אחרי בדיקה תקינה.
- ה-AI ממלא טיוטה בלבד. הבדיקה מבנית ולא רפואית: **אחריות הנכונות הקלינית שלך**.

- **לא הורץ מול ספק AI אמיתי.** נבדק עם מודל מזויף בלבד (כולל מעבר מלא עד הוספה). ההרצה הראשונה צריכה להיות בסקירה מלאה.
- הממשק משתמש בתבנית הקיימת: אותן שאלות, בדיקות גופניות ורשימות בדיקות (33 בסיסיות, 9 בדיקות המשך). הוספת פריטים חדשים (למשל למקרה לא קרדיאלי) תדרוש הרחבה של התבנית; ראו התכנון בשיחה.
