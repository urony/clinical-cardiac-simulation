# חיבור לאשף ה-API

אשף ה-API הוא פרויקט נפרד (`..\א - כלים שונים\כלי למציאת API`, מאגר `urony/api-wizard`). הוא עוזר למורה להשיג מפתח, ואינו מקבל או שומר מפתחות.

## מה כבר מחובר בצד הסימולטור

- בעמוד "הקמת כיתה" (`#/setup`) מוצג קישור "אשף ההשגה" אל כתובת האשף עם `?tool=cardiac-simulator`. הכתובת נקראת מ-`data/links.json` (`wizardUrl`). כתובת ריקה (`null`) מסתירה את הקישור.
- בדף הסימולטור הרגיל יש קישור "למורים: הקמת כיתה".

## מה נשאר לעשות בצד האשף (לא בוצע; הפרויקט נפרד)

ברשימת הכלים של האשף (`data/tools.json`) כבר קיימת רשומה `cardiac-simulator` עם `officialUrl: null` ו-`supportedProviders: []`. הרשומה המוצעת נמצאת ב-[wizard-tool-entry.json](wizard-tool-entry.json). כדי להפעיל את החזרה מהאשף לעמוד ההקמה:

1. **לפרסם את הסימולטור** (למשל GitHub Pages) ולקבל כתובת https אמיתית.
2. **למלא `officialUrl`** בכתובת הסימולטור עם `#/setup` (האשף מציג לפיה את הכפתור "חזרה לכלי"). כתובת צפויה, שלא אומתה: `https://urony.github.io/clinical-cardiac-simulation/#/setup`.
3. **להחליט על `supportedProviders`:** ברשומה המוצעת רק `openai`, כי זה המסלול היחיד שהיה בשימוש בפועל. ספקים אחרים (Gemini, Groq, OpenRouter, Mistral, xAI) מוגדרים בסימולטור אך לא נבדקו מול שירות אמיתי. אחרי בדיקה חיה אפשר להוסיף אותם ולמלא `compatibilityVerified` בתאריך הבדיקה.
4. להריץ באשף `npm run validate` ו-`npm test`.

## נקודה שדורשת החלטה

האשף מסביר כברירת מחדל שמפתח API הוא סוד ושאין להעביר אותו לתלמידים. בסימולטור, לעומת זאת, **המפתח נכלל בקישור הכיתה שנשלח לתלמידים** (בחירה מכוונת; ראו README). כדאי שהאשף יציג עבור כלי זה את הנוסח של \`pasteInstructions\`, ולא רק את האזהרה הכללית, כדי שלא תהיה סתירה.
