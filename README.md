# המרפאה הקרדיולוגית הווירטואלית

כלי סימולציה לימודי לתלמידי מדעי הבריאות בתיכון. התלמיד מנהל קבלה בקופת חולים בשפה חופשית, מבצע בדיקה ובדיקות, מנמק החלטות לפרופ׳ שחף, כותב רשומה רפואית ומסביר למטופל. המערכת מפיקה משוב איכותני ודוח PDF.

זהו **אתר סטטי** (React + Vite, בלי שרת). הדפדפן פונה ישירות לספק ה-AI. הספקים והמודלים מוגדרים ב-`data/providers.json`. **Gemini** (מסלול חינמי) נבדק בסימולציה מלאה ומומלץ; OpenAI היה בשימוש; **Groq** עבד בבדיקת חיבור אך המכסה החינמית נגמרה מהר; xAI, OpenRouter ו-Mistral מוגדרים אך **לא נבדקו מול השירות האמיתי**. מורה יוצר **קישור כיתה** שמכיל את המפתח; תלמידים פותחים את הקישור ולא רואים שדה מפתח.

## הרצה ובדיקה מקומית

דרישות: Node.js `>=22.13.0`.

```bash
npm ci --ignore-scripts   # התקנה לפי קובץ הנעילה
npm run dev               # שרת פיתוח, בדרך כלל http://localhost:5173
npm run build             # בנייה ל-dist/
npm run preview           # הצגת הבנייה המקומית
npm test                  # בנייה ואז כל הבדיקות (לא פונות לשירות AI; הספק מוחלף בזיוף)
npm run typecheck
npm run lint
```

הבדיקות לא משתמשות במפתח אמיתי ולא שולחות בקשות רשת. הרצת הסימולציה עם AI אמיתי דורשת מפתח API.

## מבנה

- `src/` — הממשק: `App.tsx` (הסימולטור), `TeacherSetup.tsx` (הקמת כיתה) ונקודת הכניסה `main.tsx`.
- `lib/` — הלוגיקה: `simulation.ts` (שלבי השיחה והבדיקות), `feedback.ts` (המשוב), `ai-client.ts` (שכבת ספקים אחידה: מתאם Responses ומתאם Chat Completions), `providers.ts` (קריאת הגדרות הספקים), `case-catalog.ts` (רשימת מקרים בטוחה לדפדפן), `case-data.ts` (קריאת נתוני מקרה), `case-loader.ts` (טעינה עצלה), `session-store.ts` (שמירת התקדמות בדפדפן), `class-link.ts` (קישור כיתה והגבלות רכות).
- `data/cases/` — קבצי המקרים (JSON) וקטלוג `index.json`.
- `data/source/` — קבצי ה-Excel המאושרים. `scripts/import-case-data.py` ממיר אותם ל-JSON (דורש Python ו-openpyxl; לא נבדק על מחשב זה).
- `tests/` — בדיקות. `types/` — הגדרות טיפוסים.

## מקרים

המקרים נטענים מהקטלוג `data/cases/index.json`, כל אחד כקובץ נפרד שנטען רק כשהתלמיד בוחר אותו. הוספת מקרה: קובץ JSON תקין בתיקיית `data/cases/` ושורה בקטלוג. `tests/case-catalog.test.mjs` בודק מזהים כפולים, שדות חסרים, אי-התאמה לקובץ, וקובץ שלא נכלל בקטלוג. התלונה המרכזית והמגבלה `maxAnamnesisFacts` נכתבות כרגע ידנית בקטלוג (אינן בקבצי ה-Excel).

עובדות קליניות, תוצאות, פרסונה ורובריקות מקורן בקבצי הנתונים המאושרים, לא בקוד. אין לשנות עובדה קלינית בלי אישור.

## הוספת מקרים (רק אצלך)

**ממשק ניהול מקומי** (דף שרץ על המחשב שלך בלבד): תיאור מקרה, הפקת טיוטה בעזרת AI או עם ה-AI שלך בצ'אט, סקירה ועריכה, הוספה לקבצי הפרויקט ופרסום באתר, הכול בכפתורים ורק אחרי אישור מפורש. הפעלה: לחיצה כפולה על `start-admin.bat` או `npm run admin` (עם `-- --demo` להכרות בלי AI). ראו [docs/case-admin.md](docs/case-admin.md). קיים גם כלי שורת פקודה לאותה מטרה: [docs/case-tool.md](docs/case-tool.md).

## קישור כיתה (למורים)

פותחים את הכתובת של האתר עם `#/setup`, מזינים מפתח API, בוחרים ספק ומודל, מגדירים הגבלות ותוקף, ומקבלים קישור לשליחה לתלמידים (`#c=…`). ההגדרות נשמרות בחלק ה-`#` של הכתובת, שאינו נשלח לשרת.

- **המפתח גלוי בקישור ובדפדפן של התלמיד** ואינו מוצפן; תלמיד שמבין יכול לחלץ אותו. לכן המורה מקבל אזהרה לפני יצירת הקישור, ומומלץ מפתח ייעודי חינמי או עם תקרת הוצאה. העלות והאחריות על המורה.
- **ההגבלות רכות** (מספר פניות לתלמיד, אורך תשובה, תוקף): הן נאכפות בדפדפן ואפשר לעקוף אותן. ההגנה האמיתית היא המכסה אצל הספק.
- התלמיד רואה הודעה על כך ששיחתו נשלחת לספק, לפי `dataNotice` של הספק ב-`data/providers.json`.
- כתובת הספק לא נקראת מהקישור, אלא רק מ-`data/providers.json`.

### השגת מפתח: אשף ה-API

בעמוד ההקמה יש קישור לאשף ה-API (פרויקט נפרד) עם `?tool=cardiac-simulator`. כתובת האשף ב-`data/links.json` נגזרה מכתובת המאגר שלו ולא אומתה כאתר חי. מה שנשאר לעשות בצד האשף (כתובת החזרה והספקים הנתמכים) מתואר ב-[docs/wizard-integration.md](docs/wizard-integration.md).

הפעלה חד-פעמית בהגדרות המאגר ב-GitHub: **Settings, ואז Pages, ואז Build and deployment, Source: GitHub Actions**. אם הרצה ראשונה נכשלה לפני ההפעלה, אפשר להריץ אותה שוב מהלשונית Actions (Re-run jobs).

## כשלים והגבלות

- **הודעות כשל בעברית** (`lib/ai-client.ts`, `failureMessages`): מפתח שנדחה, מכסה שנגמרה, הגבלת קצב, מודל לא זמין, ספק שאינו זמין, תשובה לא תקינה, חיבור שנפל ותשובה שמתעכבת מדי (60 שניות). אין "שיחה מדומה": כשאין חיבור או שהמכסה נגמרה, התלמיד רואה הודעה ברורה והסימולציה לא ממשיכה.
- **ניסיון חוזר:** פעם אחת בלבד, ורק לנפילת חיבור או כשל 5xx של הספק. שגיאות מפתח, מכסה וקצב לא נשלחות שוב.
- **שאלה שלא נענתה** חוזרת לתיבת הכתיבה של התלמיד ואינה נשארת בשיחה.
- **הגבלות רכות שהמורה מגדיר:** מספר פניות לתלמיד, פניות לדקה, אורך תשובה ותוקף הקישור. הן נאכפות בדפדפן ואפשר לעקוף אותן; ההגנה האמיתית היא המכסה אצל הספק.
- **מודלים שחושבים** (Gemini, Groq `gpt-oss`, Grok): החשיבה הנסתרת נספרת במגבלת האורך, ולכן בלי מרווח הם עלולים להחזיר תשובה ריקה. בהגדרות הספק (`reasoningEffort`, `outputTokenHeadroom` ב-`data/providers.json`) מבוקשת חשיבה קצרה ונוסף מרווח טוקנים. תשובה שנחתכה מדווחת בנפרד, עם הסיבה (`finish_reason`) שמוצגת למורה ב״בדוק חיבור״. ההגדרות האלה נגזרו מהתיעוד ולא נבדקו מול השירותים.
- פרטי הספק (בדרך כלל באנגלית) נשמרים ב-`error.detail`, ומוצגים למורה ב״בדוק חיבור״, לא לתלמיד.

## מצב ומה הלאה

- **נתוני המקרה גלויים לתלמיד** (הם קבצים באתר הסטטי). זו החלטה מכוונת.
- **שמירת ההתקדמות** היא בדפדפן בלבד; קוד השחזור פועל רק באותו דפדפן ומכשיר. כל מטופל נשמר בנפרד תחת אותו קוד: אפשר לחזור למסך הפתיחה בכל שלב (הכפתור בראש הדף ובסוף התהליך), לעבור למטופל אחר, ולהמשיך לאחר מכן מהמקום שעצרת.
- **תוצאות בדיקות המשך** (הולטר, אקו וכו') מוצגות רק משלב 10: עד אז הן לא מופיעות בתיק הבדיקות, ברשומה הרפואית ובדוח הביניים, והתלמיד מקבל הודעה שהן בדרך.
- **ספקים:** רק OpenAI היה בשימוש; האחרים לא נבדקו מול שירות אמיתי. "בדוק חיבור" בעמוד ההקמה שולח בקשה קצרה במפתח המורה, ביוזמתו.
- **פרסום:** ראו "פרסום ב-GitHub Pages" להלן.
